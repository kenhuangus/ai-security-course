Step 0

An incident is not a vulnerability

AIVSS scores a vulnerability in a deployment context, so the first honest step is saying which one. The ExploitGym chain contained at least four distinct defects.

What we anchor on

  • The stage-1 sandbox escape
  • It turned a contained evaluation into a five-organization intrusion
  • Scored as CVE-2026-65617, deserialization in package handling, CWE-502

What the sourcing actually supports

  • Hugging Face describes "a zero-day in the package registry cache proxy" and names no CVE
  • The CVE association comes from secondary reporting and is [S], not [P]
  • Both candidate CVEs were published 2026-07-27, after the incident

Hugging Face postmortem [P]; CVE association [S]. Full working in research/synthesis-capstone.md. Teaching exercise.

Most people skip Step 0 and score "the incident", which is not a thing AIVSS can take. Make the room say out loud which defect is being scored. Flag the confidence honestly: we are scoring a CVE that secondary reporting associates with the escape, and the association could be wrong.

First friction point

The framework wants v4.0. The record has v3.1.

⚠AIVSS v0.8 specifies CVSS v4.0 as CVSS_Base. NVD publishes only a CVSS v3.1 score for CVE-2026-65617: 8.8 HIGH. No v4.0 vector exists for it.

A framework that requires inputs most of the existing corpus does not have cannot be applied without the assessor either computing a v4.0 vector themselves or substituting quietly.

What this exercise does

  • Substitutes the v3.1 score and says so here
  • Carries a sensitivity range rather than claiming a precision the input does not support

AIVSS v0.8, Section 3.3 [P]; NVD record for CVE-2026-65617 [P]. Teaching exercise.

This is the most useful slide in the capstone for practitioners, because it is the problem they will hit in the first ten minutes of trying this on their own backlog. Say plainly: we found this by using the framework, not by reading it.

A genuine strength of v0.8

  • A 3.3-point swing in the input moves the output by 0.5
  • Under v0.5 averaging the same swing moved it by roughly 1.65

The counterpoint, same slide

  • Everything in the Critical band looks alike
  • Seven of AIVSS's own ten core risks are also Critical
  • Compressing uncertainty is not the same as prioritizing

Arithmetic in research/synthesis-capstone.md. Teaching exercise.

Both cards belong on the same slide on purpose. The design compresses input uncertainty, which is real and good. It also compresses everything toward the top, which is real and awkward. Presenting one without the other is advocacy rather than teaching.

Where a reasonable assessor could differ

Impact, argued both ways

Contained — wrong

  • The blast radius crossed into a third party's production estate

Significant (5) — selected

  • Five datasets matching ExploitGym and CyberGym challenges accessed
  • Hugging Face states no other customer content was breached
  • Serious, bounded, not existential

Critical (10) — arguable

  • Root on production nodes, 136 secret keys, source-control token minting
  • Total compromise of the affected estate regardless of what was taken

The exercise selects Significant and shows Critical beside it. Where a reasonable assessor could go either way, showing the fork is more honest than defending the pick.

Hugging Face postmortem [P]. Teaching exercise.

This is a good place to take the room's opinion before revealing the choice. Ask for hands on Significant versus Critical. The split is usually close, which makes the point better than any argument: a model whose input is contested produces an output that is contested.

Step 3

It does not take one branch

research/synthesis-routing-tree.md and synthesis-capstone.md; incident facts [P]. Routing logic is ours.

Five routes, four organizations. Nobody in this incident had a process that produced five filings, and it is not obvious anybody should. The realistic question for the room is which two of the five they would actually file, and what is lost by skipping the other three.
