Module 1

SDL AND PROACTIVE DEFENSE

Which classical gates survive, which need new evidence, and which are entirely new. With both sides of the capability question stated honestly.

Every capability number labelled with the benchmark that produced it

The promise to make at the start: no capability number in this module appears without the benchmark that produced it, and where a source reports a failure the failure is on the slide with the same weight as the success. If the room has been to three vendor talks this quarter, that promise is why they should stay.

The module thesis

Finding more bugs is not the binding constraint

The instinct when offensive capability rises is to find more. The measured evidence says the constraint sits downstream of discovery, in triage, patching and deployment.

⚠An organization that doubles its discovery rate without changing its triage and deployment capacity has converted a security investment into a backlog.

Derived in research/w3-sdl.md from Forescout [P], Akrites via Infosecurity [S], and CVE volume data [S].

Open here and never leave it. Everything in the module either supports this or is a consequence of it. Akrites states the same point institutionally by measuring success in patch deployment rather than patch publication, which comes up again in Module 3.

Measured, not projected

Three numbers from three sources

Forescout Vedere Labs, 2026-04-14 [P]; Infosecurity Magazine 2026-08-19 [S] and 2026-04-15 [S].

The 4-of-72 number is the one to dwell on. That run produced four genuine, confirmed zero-days, so the tooling works. It also produced 68 things that were not. Both halves are the finding.

The classification row is the quietly alarming one. A model that finds a real bug and then describes it wrongly is worse than one that finds nothing, because the wrong description is what reaches the triage queue and gets acted on.

The row that deserves its own slide

Autonomy adds failure modes, it does not only remove them

The Unit 42 agent started an HTTP file server instead of using an isolated staging directory, and exposed the entire operation. Researchers describe this as a novel operational-security risk that would not exist under a manual workflow.

◆This cuts both ways. An autonomous defensive agent can expose your own operation in exactly the same manner, and for exactly the same reason.

Unit 42, Palo Alto Networks [P].

Worth pausing on. Most of the room is thinking about attackers using agents. The transferable lesson is that any autonomous system introduces mistakes a human operator would not make, and the defensive agent you deploy is subject to the same class of error.

Reading capability claims

Three benchmarks that get quoted as one curve

UK AI Security Institute [P] for both AISI series; Forescout Vedere Labs [P]. Each measures a different thing.

The single most useful habit this module can install: when someone shows a rising capability line, ask which benchmark each point came from. These three get blended into one narrative constantly, and they are not commensurable.

The most important caveat in the module

The evaluators will not say it works against defended systems

AISI states plainly that it cannot say whether Mythos Preview could attack well-defended systems, because the evaluation environments contain no active defenders, no defensive tooling, and no penalty for triggering security alerts.

⚠Demonstrated capability is described as autonomously attacking small, weakly defended and vulnerable enterprise systems where network access has already been gained.

UK AI Security Institute evaluation of Claude Mythos Preview [P].

This is the slide that separates this course from vendor content. The organization that ran the evaluation is telling you what its own numbers do not establish. Every capability figure in this module sits inside this caveat, and the caveat is theirs, not ours.

A correction worth making

Read the credit line, not the headline

The common framing

  • "A model discovered and exploited a 17-year-old kernel bug autonomously"

What the advisory says

  • FreeBSD credits "Nicholas Carlini using Claude, Anthropic"
  • That is a joint credit describing a researcher working with a model
  • Announced 2026-03-26, before the public Mythos announcement

The finding is still remarkable. It is a human-plus-model result, and describing it as autonomous discovery misstates what was demonstrated.

FreeBSD-SA-26:08.rpcsec_gss [P].

Small correction, large habit. The credit line on an advisory is primary evidence about how a finding was produced, and it is nearly always available and nearly never read.

Adversary adoption is real and narrower than headlines

What was observed

  • A Chinese-speaking actor running an open-weights model inside the Hermes Agent framework
  • An MCP server translating natural language into internet-scan queries
  • An automated vulnerability-intelligence pipeline aggregating disclosures from 17 sources over Telegram
  • Trial use of six other commercial models, reading as market evaluation

Seven CVEs targeted. The split matters more than the count.

  • Autonomous, failed: 3 CVEs
  • Manual, successful: 2 CVEs
  • Manual, attempted or non-functional: 3 CVEs
⚠Every success in the campaign was manual.

Unit 42, Palo Alto Networks [P]. Session documented 2026-05-07. CVE identifiers in research/w4-offensive.md.

The campaign is genuinely alarming for reconnaissance and genuinely unimpressive for exploitation. Researchers note that targets with weaker default configurations would have been susceptible, which is a statement about the target population rather than about model capability.

Both directions, stated honestly

Both sides got better at finding. Neither got reliable at exploiting.

Defenders gained real capability

  • Four confirmed zero-days from an agentic framework
  • And 72 raw alerts, false positives, and misclassifications in the same run

Attackers gained real capability

  • Reconnaissance compressing hundreds of hours into minutes
  • Autonomous exploitation failed in both attempts

The engineering consequence lands on triage capacity, which is where this module started.

Forescout Vedere Labs [P]; Unit 42 [P]. Analysis in research/w3-sdl.md.

Close the capability section here and pivot to the SDL. If the room only remembers one line, make it that the symmetry holds at the finding stage and breaks at the exploiting stage, and that the pressure therefore lands on triage.

The SDL, gate by gate

One gate survives untouched

Classification derived in research/w3-sdl.md from the incident and capability evidence. The verdicts are ours.

Say clearly that this classification is our analysis rather than a citation. We checked whether any published framework already names these gates so we could cite instead of propose, and did not find one; that open question is recorded in gaps.md.

Gate 1 · needs new evidence

Requirements: add an autonomy declaration

What to add

  • What the system may do without human approval
  • The blast radius of each such action

Why it belongs here

  • The Meta Sev-1 was an unreviewed agent action in an ordinary workflow
  • That is a requirements failure before it is a runtime failure

An autonomy declaration is a requirement, not a runtime setting. If it is discovered in configuration, it was never reviewed.

Meta incident [S]; analysis in research/w3-sdl.md.

This is the gate most likely to be actionable for the room next week, because writing an autonomy declaration costs nothing and immediately exposes disagreement between teams about what the agent is allowed to do.

Gate 2 · needs new evidence

Threat modeling: STRIDE does not reach these

What classical STRIDE does not model

  • Goal drift
  • Memory poisoning
  • Delegated authority

What MAESTRO adds

  • Seven layers, decomposed individually
  • An explicit cross-layer step, which is where agent failures actually live

Evidence artifact

  • A threat model naming every tool
  • Every trust boundary
  • Every principal the agent can act as
◆Lab 1 runs this gate against a reference architecture two weeks from launch.

MAESTRO: cloudsecurityalliance.org/blog/2025/02/06/agentic-ai-threat-modeling-framework-maestro (Huang, 2025) [P].

MAESTRO is Ken's framework, published through CSA. Say so and then hand straight to Lab 1, which is built on it. The cross-layer step is the part with no STRIDE equivalent and it is where Lab 1 spends its time.

Gate 3 · needs new evidence

Design review: an instruction in a system prompt is not a control

Reviewers must sign off on where controls live. A constraint written into the context window competes for attention with everything else in the context window, and it fails open.

⚠Evidence artifact: a control-placement table showing which constraints are enforced outside the model.

Derived in research/w3-sdl.md; the failure mode is walked in detail in Module 2.

This is the sentence the whole course is organized around. Module 2 shows a real agent walking past an instructional control across five trust boundaries, and Lab 1 Task 4 makes the room rewrite one.

Gate 4 · survives unchanged

Static analysis is fine

It still finds what it always found. Unchanged in kind, larger in volume.

✓The only green gate in the diagram. Do not spend budget re-examining it.

research/w3-sdl.md.

Deliberately short. A module that says everything must change is not credible, and being specific about what does not change is what makes the other eight verdicts believable.

Gate 5 · needs new evidence

Supply chain: the scope widens past packages

What is now in scope

  • Packages, as before
  • Models
  • Datasets
  • Prompts
  • Tools and skills

Why, concretely

  • The ExploitGym escape ran through a package registry cache proxy the agent was permitted to use
  • The route out was a sanctioned dependency path

A dependency review that stops at packages misses the paths an agent is most likely to take, because those are the ones you approved.

Hugging Face postmortem [P]; analysis in research/w3-sdl.md.

Connect back to Lab 1 Chain A, which is this exact route found by threat modelling before it ran. Anyone who did the lab has already written this finding down.

Gate 6 · needs new evidence

Dynamic testing: one passing run proves nothing

A system that samples does not have a single behaviour to test. Add non-deterministic repetition.

⚠Evidence artifact: a pass rate over N runs with a stated threshold, rather than a pass or fail on one.

research/w3-sdl.md.

Ask how many people have a CI job that runs an LLM-backed test exactly once and gates the build on it. The hands are the slide.

Gate 7 · needs new evidence

Penetration testing: the tool surface is the attack surface

What goes in scope

  • The agent's tool surface, not only its endpoints
  • The credentials it holds
  • The principals it can act as

The AISI caveat, in reverse

  • Results from an environment with no active defenders do not transfer
  • That cuts against your own test results too, not only against capability claims

UK AISI [P] for the caveat; scoping analysis in research/w3-sdl.md.

Nice symmetry to point out: we used the AISI caveat earlier to discount attacker capability claims. The same logic discounts our own optimistic pentest results, and intellectual honesty means applying it in both directions.

Gate 8 · needs new evidence

Release approval: two gates feed it directly

Approval must reference evaluation results and containment posture, not only test pass or fail.

⚠A release that has not passed containment review and guardrail regression has not established that its controls hold when the agent stops cooperating.

research/synthesis-sdl-vnext.md.

Those two are the only new gates that feed release approval directly in the diagram. Everything else feeds an earlier stage. That is deliberate: they are the two that answer "what happens when this goes wrong in production".

Gate 9 · needs the most change

Your analysis tooling may refuse to help you

When Hugging Face analysts tried to reverse-engineer recovered payloads and C2 artifacts, the commercial frontier models they reached for first refused the work. Provider guardrails treated analysing an exploit the same as launching one.

⚠The team fell back to running an open-weights model on their own infrastructure to finish the investigation.

Hugging Face postmortem [P], which names the models and the fallback.

This is the least anticipated finding in the whole course. Almost nobody's incident response plan records a dependency on a third party's content policy, and this is a documented case of that dependency failing at the worst moment.

Three consequences for the plan

What to write into incident response this quarter

  • Analysis capability that depends on a third party's content policy is an availability dependency. Put it in the plan's dependency list beside your other vendors.
  • A guardrail evaluating a submission without context cannot separate an analyst from an attacker, because the two submissions are textually identical. This is not a bug someone will fix for you.
  • On-premises open-weights capability is an incident response control, not only a cost decision. It also keeps attacker data in-house.
⚠Exit criterion: the plan names an analysis capability available when provider guardrails refuse, and that capability has been exercised.

Consequences derived in research/w3-sdl.md from the Hugging Face postmortem [P].

The last three words of the callout matter most. Naming a fallback model in a document is not the control. Having run it against a real artifact is.

The genuinely new work

Eight new gates, and what a reviewer signs

New gateSigned artifact
Data provenanceCorpus manifest with origin, licence, integrity hash. No corpus of unattested origin

research/synthesis-sdl-vnext.md. These are proposed, not cited from a published framework.

Every row names an artifact rather than an activity, deliberately. "Do threat modelling" is not a gate. "A reviewer signed this specific document" is. If the room adopts one row, push them toward containment and blast radius.

The clause that earns its place

Test the guardrail after compaction, not at turn one

If safety instructions live in the context window, they are subject to the context window's behaviour. A suite that only probes the first turn measures the wrong thing.

⚠Whether context compaction actually caused the ExploitGym behaviour is a hypothesis and is not established [H]. The gate is worth having either way, because the control is in the wrong place regardless of why it failed.

research/w5-telemetry.md and w3-sdl.md. The compaction explanation is tagged [H] throughout this course.

Note the shape of the argument, because it is a good one to reuse. We do not need to resolve why the guardrail failed to know that a guardrail living inside the context window is badly placed. The governance consequence survives the uncertainty.

If you adopt one gate

Containment review is the spine of the course

All three incidents in this course are the same failure: a boundary that was expected to hold, and that held only as long as the agent kept cooperating.

⚠Exit criterion: a written statement of what the agent can reach if fully compromised, with egress rules enforced outside the agent. The reviewer signs that containment does not depend on the agent's cooperation.

research/w3-sdl.md and w6-incidents.md.

This slide is the hinge into Module 2, which spends its whole length on one incident where exactly this was missing. If the schedule is tight, cut earlier gate slides rather than this one.

Module 1 in five lines

What to take back to work

  • Budget for triage and deployment before you budget for discovery. Doubling findings without changing throughput buys a backlog.
  • When someone shows you a capability curve, ask which benchmark each point came from.
  • Write an autonomy declaration into requirements. It costs nothing and surfaces disagreement immediately.
  • Put your analysis-tooling dependency in the incident response plan, and exercise the fallback.
  • Move one control this quarter from the system prompt to somewhere the agent cannot argue with.

Drawn from research/w3-sdl.md, w4-offensive.md, and synthesis-sdl-vnext.md.

Five lines, no new material. If you are running short, land here and shorten the gate walkthrough rather than skipping the takeaways.
