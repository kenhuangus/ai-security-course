Agent telemetry fields

Thirty-seven fields across seven groups. Each one was derived by taking a phase of the July 2026 ExploitGym intrusion and asking which single field would have surfaced it, then checking that field against the OpenTelemetry GenAI semantic conventions.

Coverage result. Of the 18 reconstructed attack phases, 2 are covered by an existing convention attribute, 2 partially, and 14 are not covered at all. Hugging Face reconstructed the intrusion from infrastructure telemetry, not agent telemetry.

How to read the OTel column

Yes means an attribute in the OpenTelemetry GenAI semantic conventions covers the field. Partial means an attribute exists but does not carry the risk-relevant part of it. No means nothing in the conventions covers it.

Attribute names were extracted from the GenAI semantic conventions registry on 2026-08-27. The conventions moved there from the main OpenTelemetry documentation site, which now serves a redirect notice.

The cheapest high-value addition. memory.record.provenance. The conventions already record what was retrieved and from which store. They do not record who put it there. The write path already knows the answer, so emitting it costs almost nothing.
