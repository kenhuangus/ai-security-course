Version 0.8, the gap-closing model

AIVSS v0.8 primer

Version 0.8 replaced the averaging model in v0.5 with one that closes part of the distance between a CVSS base score and 10.0. The change matters because averaging pulled severe technical vulnerabilities down, which is the wrong direction for a framework whose purpose is to express amplification.

The formula

Risk_Gap  = 10 − CVSS_Base AARS      = Risk_Gap × (Factor_Sum / 10) × ThM AIVSS_raw = (CVSS_Base + AARS) × Mitigation_Factor AIVSS     = RoundHalfUp(AIVSS_raw, 1)

The shape of it is worth reading before the variables. AARS can only ever be a fraction of the headroom left above the CVSS score, so the result can rise toward 10.0 and can never fall below the technical severity it started from. AARS is an intermediate value and the document is explicit that it is not the reported output.

Risk_GapThe headroom agentic capability can contribute on top of the technical vulnerability0.0 to 10.0Derived

What changed from v0.5, and why it matters

v0.5  AIVSS = ((CVSS_Base + AARS) / 2) × ThM v0.8  AIVSS = (CVSS_Base + Risk_Gap × (Factor_Sum / 10) × ThM) × Mitigation_Factor

Agentic AI Tool Misuse carries a CVSS base of 9.4. Under v0.5 it scored 8.7, so adding agentic capability made the number smaller. Under v0.8 the same risk scores 9.9. This is worth teaching as a scoring-design defect and its repair rather than as an endorsement of the framework.

Three caveats to carry with the number

Ordinal inputs, interval arithmetic. Section 3.2 of the v0.8 document is titled "Important Statistical Caveat: Ordinal vs. Interval Scales". The framework itself flags that doing arithmetic on ordinal severity inputs is not fully sound. Present the caveat in the same breath as the formula.
The 0.67 mitigation floor is a declared assumption. The document describes it as a provisional anchor set by framework design consensus, open to community review and awaiting empirical calibration. The stated reasoning is that no mitigation fully eliminates residual risk from agentic amplification.
Almost everything lands Critical. Eight of the ten core risks score Critical and the other two score High. A severity model whose outputs cluster at the top has limited power to prioritize, which is part of why the AIVSS-SSVC decision track exists. Scoring and prioritization are separate questions and the capstone runs both.
On the default. The document sets ThM to 0.97 by default and argues it should sit near the actively-attacked value, because agentic exploits are often natural language that needs no compilation and because offensive agentic systems can turn a raw proof of concept into a working exploit. That is a design judgment stated by the framework, not a measurement.
